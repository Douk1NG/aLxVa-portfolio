# aLxVa Portfolio — Agent Reference

This document summarizes how the portfolio works so an agent can onboard quickly without re-exploring the whole codebase.

## What this project is

A **static, bilingual (EN/ES) personal portfolio** built with **Vite + React**. It is a **single-page site** with three visible sections: Hero, Experience, and Projects. Content is driven by typed data files and translation keys, with some files auto-generated by an external **Portfolio Management Tool**.

Deployed as a **static export** to **GitHub Pages** at `/aLxVa-portfolio`.

## High-level architecture

```
index.html              → HTML shell
main.tsx                → React entry (MotionProvider, LanguageProvider, Main)
components/main.tsx     → Page shell + entrance animation
components/sections/portfolio-section.tsx
  ├── hero/             → Sticky sidebar (name, bio, contact pills)
  └── content column
      ├── experience/   → Job history cards
      └── projects/     → Project cards
```

**Data flow:**

1. **Structural data** (company names, URLs, skill lists) lives in `data/*.ts`, often re-exporting from `data/gen/*.gen.ts`.
2. **Translatable strings** use dot-notation keys (e.g. `exp.job2.title`) stored in `translations/`.
3. Components call `t(key)` via `useLanguageSwitcher()` to resolve the current language.
4. Non-translatable fields (e.g. `company: 'Mántum'`) are rendered directly.

## Page layout

`PortfolioSection` uses a **two-column CSS grid** (`portfolio-grid` in utilities):

- **Left (`hero-column`)**: Hero section — language switcher, name, description, info tags (email, GitHub, LinkedIn, CV, etc.).
- **Right (`content-column`)**: Experience and Projects stacked with `var(--content-gap)` spacing.

Both columns use the shared `glass-gradient` visual style.

## Sections in detail

### Hero (`components/sections/hero/`)

| File               | Role                                                      |
| ------------------ | --------------------------------------------------------- |
| `hero-section.tsx` | Composes header, main, footer                             |
| `hero-header.tsx`  | `PillLanguageSwitcher` + decorative year                  |
| `hero-main.tsx`    | Name, surname (gradient), description — all via `t()`     |
| `hero-footer.tsx`  | Renders `infoTags` from `data/info-tags.ts` as pill links |

`hero-footer` resolves hrefs with `NEXT_PUBLIC_BASE_PATH` for GitHub Pages subpath routing. Supports per-language URLs via `hrefByLanguage` on `InfoTag`.

### Experience (`components/sections/experience/`)

- `experience-section.tsx` — `SectionLayout` + `SectionHeader` (Briefcase icon).
- `experience-main.tsx` — Maps `useExperience()` into `ExpandableCardGrid` / `ExpandableCard`.
- Compact view: title, company, short duration.
- Expanded view: `SectionItemExpanded` with location, long duration, description, skill tags.

### Projects (`components/sections/projects/`)

- Same expandable pattern as Experience.
- Compact: title + `key_description`.
- Expanded: full description, tech stack tags, optional GitHub / demo action buttons.

### Not rendered (but prepared)

- **Contact section**: translations exist in `translations/sections/contact/` but no UI component uses them yet.
- **Skills section**: `skillsData` exists and is exported via `scripts/export-data.ts`, but skills only appear inline on experience/project cards — no dedicated Skills section in the layout.

## Internationalization (i18n)

### Languages

`en` and `es` — type `Language` in `types/language.ts`.

### Provider chain

```
LanguageProvider (components/providers/language-provider.tsx)
  → useLanguageProvider() (hooks/useLanguage.ts)
  → LanguageContext { language, setLanguage, t }
```

### Translation registry

`translations/index.ts` merges section bundles:

- `navigation`, `hero`, `skills`, `projects`, `experience`, `contact`

Each section has:

- `index.ts` — hand-maintained keys + spreads from `gen/*.gen.ts`
- `gen/*.gen.ts` — **auto-generated** by Portfolio Management Tool (do not hand-edit)

### Usage in components

```tsx
const { t, language, toggleLanguage } =
  useLanguageSwitcher()
// or
const { t } = useLanguageContext()
```

Missing keys log a console warning and return the key string.

### Tests

`test/translations/translations.test.ts` enforces EN/ES key parity and non-empty values.

## Data layer

### Pattern

```
data/foo-data.ts          → thin re-export
data/gen/foo.gen.ts       → generated content (DO NOT EDIT)
types/foo.ts              → TypeScript types
```

### Current datasets

| File                 | Type           | Used by                              |
| -------------------- | -------------- | ------------------------------------ |
| `experience-data.ts` | `Experience[]` | `useExperience` → Experience section |
| `projects-data.ts`   | `Project[]`    | `useProjects` → Projects section     |
| `info-tags.ts`       | `InfoTag[]`    | Hero footer                          |
| `skills-data.ts`     | `SkillGroup[]` | Export script only                   |

### Experience / Project shape

- **Translation keys** for: `title`, `description`, `location`, `duration.*`, etc.
- **Raw values** for: `company`, `github`, `demo`, `skills[]` / `tech[]`
- **Skills** are `Skill` objects: `{ name, icon? | svg? }` — icons from Lucide or SVG provider.

### Export bridge

`scripts/export-data.ts` dumps all data + translations as JSON to stdout for the Portfolio Management Tool:

```bash
npx tsx scripts/export-data.ts
```

## Expandable card system

Reusable pattern for Experience and Projects.

```
ExpandableCardGrid
  ├── useExpandableGrid()     → expandedIndex, isMobile, keyboard (Escape)
  ├── ExpandableContext       → shared state for children
  ├── ExpandableCard (×N)     → compact button (desktop) or inline expanded (mobile)
  └── ExpandableOverlay       → fullscreen modal + Embla carousel (desktop only)
        └── useExpandableCarousel() → arrow keys, prev/next buttons
```

**Desktop (>768px):** click compact card → overlay with carousel; navigate with arrows or chevrons; Escape or backdrop click closes.

**Mobile (≤768px):** no overlay — each card shows its expanded content inline in a bordered card. Expansion is disabled.

Shared presentation:

- `SectionItemCompact` — card preview
- `SectionItemExpanded` — two-column detail layout with `SkillTag` chips

Types: `types/shared/expandable-card.ts`

## Hooks (conventions)

Logic belongs in hooks; components stay presentational.

| Hook                    | Responsibility                                            |
| ----------------------- | --------------------------------------------------------- |
| `useLanguage`           | Context + provider state, `t()` function                  |
| `useLanguageSwitcher`   | Convenience: `toggleLanguage`, `isActive` per target lang |
| `useExperience`         | Returns `experienceData`                                  |
| `useProjects`           | Returns `{ projectsData }`                                |
| `useExpandableGrid`     | Expand/collapse state, mobile detection, body scroll lock |
| `useExpandableCarousel` | Embla sync with `expandedIndex`, keyboard nav             |
| `useMediaQuery`         | `useSyncExternalStore` wrapper for `matchMedia`           |

## Component conventions

Follow these rules when adding or changing code:

1. **Default exports** for single-file components; **named exports** for hooks and types.
2. **Import syntax matches export type** — no curly braces for default exports.
3. **Types** go in `types/` (not inline in components).
4. **Logic** goes in `hooks/` — one responsibility per hook/component.
5. **Do not modify** `package.json`, `tailwind.config`, `tsconfig.json`, or `vite.config.ts` unless explicitly instructed.

### Folder layout

```
components/
  sections/     → page sections (hero, experience, projects)
  shared/       → reusable (SectionLayout, ExpandableCard, Icon, etc.)
  ui/           → shadcn primitives (Button, Card, Toast, …)
  providers/    → React context providers
hooks/          → custom hooks
types/          → shared TypeScript types
data/           → static content
translations/   → i18n strings
```

## Common agent tasks

### Add a new experience entry

1. Update via Portfolio Management Tool (regenerates `data/gen/experience.gen.ts` and `translations/sections/experience/gen/`).
2. Or manually: add to gen files (will be overwritten on next sync) + add matching EN/ES translation keys.

### Add a new project

Same pattern as experience — `data/gen/projects.gen.ts` + `translations/sections/projects/gen/`.

### Add a new translatable string

1. Add key to the relevant `translations/sections/*/index.ts` (both `en` and `es`).
2. Use `t('your.key')` in the component.
3. Translation parity test must pass.

### Add a new visible section

1. Create `components/sections/<name>/` with `*-section.tsx` (layout) and `*-main.tsx` (content).
2. Add hook in `hooks/` if data access is needed.
3. Add types in `types/`.
4. Wire into `portfolio-section.tsx`.
5. Add translations under `translations/sections/<name>/` and register in `translations/index.ts`.

### Add a new info tag (hero footer)

Extend `data/gen/info-tags.gen.ts` (or `info-tags.ts` if hand-maintained) with `titleKey`, optional `href` / `hrefByLanguage`, and `icon` or `svg`.

## Warnings for agents

1. **Never hand-edit `*.gen.ts` files** — they are overwritten by the Portfolio Management Tool.
2. **Keep EN and ES translation keys in sync** — CI will fail otherwise.
3. **Respect `import.meta.env.BASE_URL`** (from Vite `base` config) for any internal links or static assets in production.
4. **Expandable overlay is desktop-only** — mobile always shows inline expanded cards.
5. **Config files** (`package.json`, `vite.config.ts`, etc.) are off-limits unless the user explicitly asks.
